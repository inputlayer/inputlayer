# Deployment

Run InputLayer in production with Docker, systemd, reverse proxies, and Kubernetes.

## Quick Reference

| Setting | Default | CLI Flag | Env Variable | Config Key |
|---|---|---|---|---|
| Host | `127.0.0.1` | `--host` | `INPUTLAYER_HTTP__HOST` | `http.host` |
| Port | `8080` | `--port` | `INPUTLAYER_HTTP__PORT` | `http.port` |
| Data directory | `./data` | `--data-dir` | `INPUTLAYER_STORAGE__DATA_DIR` | `storage.data_dir` |
| Log level | `info` | -- | `INPUTLAYER_TRACE_LEVEL` | `logging.level` |
| Log format | `text` | -- | `INPUTLAYER_TRACE_JSON=1` | `logging.format` |
| Admin password | auto-generated | -- | `INPUTLAYER_ADMIN_PASSWORD` | `http.auth.bootstrap_admin_password` |
| Config file | `config.toml` | `--config` | -- | -- |

## Environment Variables

InputLayer uses the `INPUTLAYER_` prefix with double-underscore separators for nested keys.
Environment variables override values from config files.

```bash
# Server binding
export INPUTLAYER_HTTP__HOST=0.0.0.0
export INPUTLAYER_HTTP__PORT=8080

# Storage
export INPUTLAYER_STORAGE__DATA_DIR=/var/lib/inputlayer/data
export INPUTLAYER_STORAGE__AUTO_CREATE_KNOWLEDGE_GRAPHS=true

# Persistence
export INPUTLAYER_STORAGE__PERSIST__ENABLED=true
export INPUTLAYER_STORAGE__PERSIST__DURABILITY_MODE=immediate

# Logging (via tracing)
export INPUTLAYER_TRACE_LEVEL=info          # trace, debug, info, warn, error
export INPUTLAYER_TRACE_JSON=1              # JSON structured logging
export INPUTLAYER_TRACE_FILE=/var/log/inputlayer/server.log  # Log to file instead of stderr

# Authentication
export INPUTLAYER_ADMIN_PASSWORD=your-secure-password

# Performance
export INPUTLAYER_STORAGE__PERFORMANCE__NUM_THREADS=4
export INPUTLAYER_STORAGE__PERFORMANCE__QUERY_TIMEOUT_MS=30000
```

## Configuration File

Create a `config.toml` for persistent configuration. Pass a custom path with `--config`:

```bash
inputlayer-server --config /etc/inputlayer/config.toml
```

Example production configuration:

```toml
[storage]
data_dir = "/var/lib/inputlayer/data"
default_knowledge_graph = "default"
auto_create_knowledge_graphs = false
max_knowledge_graphs = 100

[storage.persist]
enabled = true
durability_mode = "immediate"
buffer_size = 10000
max_wal_size_bytes = 67108864       # 64 MB

[storage.performance]
num_threads = 0                     # 0 = all available CPU cores
query_timeout_ms = 30000            # 30 seconds
max_query_size_bytes = 1048576      # 1 MB
max_insert_tuples = 10000
max_result_rows = 100000
slow_query_log_ms = 5000
max_query_memory_bytes = 8589934592 # 8 GiB per query; refused past it
max_graph_memory_bytes = 4294967296 # 4 GiB of facts per graph

[logging]
level = "info"
format = "json"

[http]
host = "0.0.0.0"
port = 8080
shutdown_timeout_secs = 30

[http.auth]
session_timeout_secs = 86400        # 24 hours

[http.rate_limit]
max_connections = 10000
max_ws_connections = 5000
ws_max_messages_per_sec = 1000
per_ip_max_rps = 100

[http.gui]
enabled = true
static_dir = "/var/lib/inputlayer/gui/dist"
```

## Health Checks

InputLayer exposes three probe endpoints. All bypass authentication.

| Endpoint | Method | Purpose | Healthy Response |
|---|---|---|---|
| `/health` | GET | General health check | `200 OK` |
| `/live` | GET | Kubernetes liveness probe | `200 OK` |
| `/ready` | GET | Kubernetes readiness probe | `200 OK` (or `503` if storage is unavailable) |

All endpoints are also available under the `/v1/` prefix (e.g., `/v1/health`).

Example health check:

```bash
curl -sf http://localhost:8080/health
```

## Docker

InputLayer provides a multi-stage Dockerfile that produces a minimal Debian-based image.

### Build the Image

```bash
docker build -t inputlayer:latest .
```

### Run a Container

```bash
docker run -d \
  --name inputlayer \
  -p 8080:8080 \
  -v inputlayer-data:/var/lib/inputlayer/data \
  -e INPUTLAYER_ADMIN_PASSWORD \
  inputlayer:latest
```

`-e INPUTLAYER_ADMIN_PASSWORD` passes the admin password from your shell's environment (set it from your secret store, not on the command line). Without it, the first boot generates the password and an admin API key and saves them to `/var/lib/inputlayer/data/credentials.toml` (see [Credentials](installation#credentials)).

The image includes a built-in `HEALTHCHECK` that polls `/health` every 10 seconds:

```dockerfile
HEALTHCHECK --interval=10s --timeout=3s --start-period=5s --retries=3 \
    CMD curl -sf http://localhost:8080/health || exit 1
```

### Image Details

The image runs as a non-root `inputlayer` user with the following defaults:

| Setting | Value |
|---|---|
| Binary | `/usr/local/bin/inputlayer-server` |
| Backup tool | `/usr/local/bin/inputlayer-backup` ([Backup and Restore](backup)) |
| Data volume | `/var/lib/inputlayer/data` |
| GUI assets | `/var/lib/inputlayer/gui/dist/`, served at `/` (`INPUTLAYER_HTTP__GUI__ENABLED=false` turns it off) |
| Exposed port | `8080` |
| User | `inputlayer`, uid/gid `999` (non-root) |

### Custom Configuration in Docker

Mount a config file and pass it via the CLI:

```bash
docker run -d \
  --name inputlayer \
  -p 8080:8080 \
  -v inputlayer-data:/var/lib/inputlayer/data \
  -v ./config.toml:/etc/inputlayer/config.toml:ro \
  inputlayer:latest \
  --config /etc/inputlayer/config.toml
```

## Docker Compose

### Basic Setup

```yaml
version: "3.8"

services:
  inputlayer:
    image: inputlayer:latest
    build: .
    ports:
      - "8080:8080"
    volumes:
      - inputlayer-data:/var/lib/inputlayer/data
    environment:
      INPUTLAYER_HTTP__HOST: "0.0.0.0"
      INPUTLAYER_HTTP__PORT: "8080"
      INPUTLAYER_STORAGE__DATA_DIR: "/var/lib/inputlayer/data"
      INPUTLAYER_STORAGE__PERSIST__ENABLED: "true"
      INPUTLAYER_STORAGE__PERSIST__DURABILITY_MODE: "immediate"
      INPUTLAYER_ADMIN_PASSWORD: "${INPUTLAYER_ADMIN_PASSWORD}"
      INPUTLAYER_TRACE_LEVEL: "info"
      INPUTLAYER_TRACE_JSON: "1"
    healthcheck:
      test: ["CMD", "curl", "-sf", "http://localhost:8080/health"]
      interval: 10s
      timeout: 3s
      start_period: 5s
      retries: 3
    restart: unless-stopped

volumes:
  inputlayer-data:
```

### With Traefik Reverse Proxy

```yaml
version: "3.8"

services:
  traefik:
    image: traefik:v3.2
    command:
      - "--providers.docker=true"
      - "--providers.docker.exposedByDefault=false"
      - "--entrypoints.web.address=:80"
      - "--entrypoints.websecure.address=:443"
      - "--certificatesresolvers.le.acme.httpchallenge.entrypoint=web"
      - "--certificatesresolvers.le.acme.email=admin@example.com"
      - "--certificatesresolvers.le.acme.storage=/letsencrypt/acme.json"
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - letsencrypt:/letsencrypt

  inputlayer:
    image: inputlayer:latest
    build: .

      - inputlayer-data:/var/lib/inputlayer/data

      INPUTLAYER_HTTP__HOST: "0.0.0.0"

    healthcheck:
      test: ["CMD", "curl", "-sf", "http://localhost:8080/health"]
      interval: 10s
      timeout: 3s
      start_period: 5s
      retries: 3
    restart: unless-stopped

volumes:
  inputlayer-data:
  letsencrypt:
```

## systemd

Create a systemd service for running InputLayer on a bare-metal or VM deployment.

### Create a System User

```bash
sudo useradd -r -s /bin/false -m -d /var/lib/inputlayer inputlayer
sudo mkdir -p /var/lib/inputlayer/data
sudo chown inputlayer:inputlayer /var/lib/inputlayer/data
```

### Install the Binary

```bash
sudo cp target/release/inputlayer-server /usr/local/bin/
sudo chmod 755 /usr/local/bin/inputlayer-server
```

### Create the Service File

Write the following to `/etc/systemd/system/inputlayer.service`:

```ini
[Unit]
Description=InputLayer
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=inputlayer
Group=inputlayer
ExecStart=/usr/local/bin/inputlayer-server \
    --host 0.0.0.0 \
    --port 8080 \
    --config /etc/inputlayer/config.toml \
    --data-dir /var/lib/inputlayer/data
Restart=on-failure
RestartSec=5
LimitNOFILE=65536

# Security hardening
ProtectSystem=strict
ProtectHome=true
ReadWritePaths=/var/lib/inputlayer/data
PrivateTmp=true
NoNewPrivileges=true
ProtectKernelTunables=true
ProtectControlGroups=true

# Environment
Environment=INPUTLAYER_TRACE_LEVEL=info
Environment=INPUTLAYER_TRACE_JSON=1
Environment=INPUTLAYER_TRACE_FILE=/var/log/inputlayer/server.log

[Install]
WantedBy=multi-user.target
```

### Enable and Start

```bash
sudo mkdir -p /var/log/inputlayer
sudo chown inputlayer:inputlayer /var/log/inputlayer

sudo systemctl daemon-reload
sudo systemctl enable inputlayer
sudo systemctl start inputlayer

# Check status
sudo systemctl status inputlayer
sudo journalctl -u inputlayer -f
```

## TLS and Reverse Proxies

InputLayer does not terminate TLS natively. Use a reverse proxy for TLS termination in production.

### Nginx

```nginx
server {
    listen 443 ssl;
    server_name inputlayer.example.com;
    ssl_certificate     /etc/ssl/certs/inputlayer.crt;
    ssl_certificate_key /etc/ssl/private/inputlayer.key;
    ssl_protocols       TLSv1.2 TLSv1.3;
    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
```

The `proxy_read_timeout` and `proxy_send_timeout` values of 300 seconds accommodate long-running WebSocket connections. The `Upgrade` and `Connection` headers are required for WebSocket support.

For HTTP-to-HTTPS redirect, add a companion server block:

```nginx
server {
    listen 80;
    server_name inputlayer.example.com;
    return 301 https://$host$request_uri;
}
```

### Caddy

Caddy automatically provisions and renews TLS certificates via Let's Encrypt:

```caddyfile
inputlayer.example.com {
    reverse_proxy 127.0.0.1:8080 {
        header_up X-Real-IP {remote_host}
    }
}
```

No additional TLS configuration is needed. Caddy handles certificates, HTTPS redirect, and WebSocket upgrades automatically.

## Kubernetes

The repository ships Kustomize manifests in `deploy/kubernetes/`. Install one
engine per tenant: each tenant gets its own namespace, volume and engine.

| Path | Contents |
|---|---|
| `base/statefulset.yaml` | The engine: one replica, non-root, probes, graceful shutdown |
| `base/pvc.yaml` | `inputlayer-data`, the engine's `ReadWriteOnce` volume |
| `base/service.yaml` | `inputlayer`, a ClusterIP Service on port `8080` |
| `base/configmap.yaml` | `config.toml`, mounted at `/etc/inputlayer/config.toml` |
| `components/ingress/` | Optional ingress-nginx Ingress with TLS |
| `overlays/tenant-example/` | A per-tenant overlay: namespace, image tag, Ingress host |
| `maintenance/maintenance-pod.yaml` | Offline volume access for [backup and restore](#backup-and-restore) |

### Install a Tenant

Copy `overlays/tenant-example` to a directory of your own. Then set the
namespace, pin the image tag and set the Ingress host. If the tenant has no
public endpoint, drop the `components` entry and the Ingress patch. Then:

```bash
kubectl apply -f my-overlays/acme/namespace.yaml
kubectl -n inputlayer-acme create secret generic inputlayer-secrets \
  --from-literal=admin-password='your-secure-password' \
  --from-literal=bootstrap-api-key='your-agent-api-key'   # optional
kubectl apply -k my-overlays/acme
kubectl -n inputlayer-acme rollout status statefulset/inputlayer
```

If you leave out `bootstrap-api-key`, the engine generates an admin API key on
first boot and stores it in `credentials.toml` on the volume:

```bash
kubectl -n inputlayer-acme exec inputlayer-0 -- cat /var/lib/inputlayer/data/credentials.toml
```

Agents in the cluster connect to `ws://inputlayer.inputlayer-acme.svc:8080/ws`.
Agents outside it connect through the Ingress at `wss://<host>/ws`.

### Single Writer

InputLayer is a single writer per data directory (see
[Persistence](persistence#single-writer)). The manifests stack three
safeguards:

1. **One replica.** `replicas: 1` on a StatefulSet. Never raise it, and never
   point an autoscaler at it.
2. **No overlap on replacement.** With one replica, a StatefulSet rolling
   update deletes `inputlayer-0`, waits for it to terminate, and only then
   creates the replacement. A Deployment's default `RollingUpdate` starts the
   new pod first. If you deploy the engine as a Deployment, use
   `strategy: Recreate`.
3. **The data-dir lock.** `ReadWriteOnce` stops a second node attaching the
   volume. Pods on the same node can still mount it, and there the engine's
   `LOCK` refuses the second writer, which exits with `in use by another
   InputLayer process`.

None of this prevents every duplicate writer. A force-deleted pod
(`kubectl delete pod --force`), or a pod on a partitioned node, can still be
running when its replacement starts. Then only the volume and the lock
remain. They do not hold on storage that attaches read-write to several nodes,
or on a filesystem whose `flock` is not shared between clients (some NFS
setups). Keep the data on block storage. Where the CSI driver supports it,
set `accessModes: [ReadWriteOncePod]` in `pvc.yaml`. Do not force-delete
the engine pod unless you know that its node is down.

### Security Context

The engine runs as uid/gid `999`, the image's `inputlayer` user (pinned in the
`Dockerfile`). `fsGroup: 999` makes a freshly provisioned, root-owned volume
writable. The root filesystem is read-only, all capabilities are dropped,
privilege escalation is off and the seccomp profile is `RuntimeDefault`. The
pod passes the `restricted` Pod Security Standard, which the example overlay
enforces on its namespace. The pod gets no service account token.
`enableServiceLinks: false` keeps Kubernetes from injecting `INPUTLAYER_*`
service variables into the engine's config namespace.

### Configuration

`base/configmap.yaml` holds `config.toml`. Environment variables override it,
and the engine image sets `http.host`, `http.port`, `storage.data_dir`,
`logging.level` and `storage.auto_create_knowledge_graphs` as environment
variables. Change those five keys in `statefulset.yaml`. A ConfigMap change does not
restart the pod, so restart it after applying:

```bash
kubectl -n inputlayer-acme rollout restart statefulset/inputlayer
```

Behind the Ingress, every request comes from the ingress controller. Set
`http.trusted_proxies` to the controller's pod CIDR. Otherwise the per-IP rate
limit and the pre-auth WebSocket cap (`ws_max_preauth_per_ip`) apply to
the controller instead of to each client. The Ingress keeps idle WebSockets
open for an hour, so the engine's `http.ws_idle_timeout_ms` decides when idle
subscriptions close.

### Probes, Shutdown and Upgrades

- The HTTP server starts only after the WAL replay. The startup probe on
  `/live` therefore sets the replay budget: 10 minutes. Raise
  `failureThreshold` for large data sets.
- `/live` drives the liveness probe and `/ready` (storage reachable) drives
  readiness. See [Health Checks](#health-checks).
- `terminationGracePeriodSeconds: 60` exceeds `http.shutdown_timeout_secs: 30`
  so the WAL flush on `SIGTERM` can finish.
- To upgrade, change the image tag in the overlay and `kubectl apply -k` it.
  The engine is down from its shutdown until the new pod finishes replay.
  Take a backup first.

### Backup and Restore

Back up and restore with the engine stopped. The maintenance pod mounts the
volume as the engine's user and holds the engine's `LOCK` while it runs. It
fails to start while an engine owns the volume, and an engine started in the
meantime refuses the volume. Point kubectl at the tenant's namespace first:

```bash
kubectl config set-context --current --namespace=inputlayer-acme
```

**Back up**

```bash
kubectl scale statefulset/inputlayer --replicas=0
kubectl wait --for=delete pod/inputlayer-0 --timeout=120s
kubectl apply -f deploy/kubernetes/maintenance/maintenance-pod.yaml
kubectl wait --for=condition=Ready pod/inputlayer-maintenance --timeout=180s
kubectl exec inputlayer-maintenance -- sh -c 'cd /var/lib/inputlayer/data &&
  find . -mindepth 1 -maxdepth 1 ! -name LOCK ! -name lost+found -print0 |
  tar --null -T - -czf -' > inputlayer-backup.tgz
kubectl delete pod inputlayer-maintenance
kubectl scale statefulset/inputlayer --replicas=1
```

The archive holds every knowledge graph, the WAL and the user and API key
store. If the engine generated its credentials, the archive also holds
`credentials.toml`. Treat the archive as a secret.

**Restore** into a new, empty volume. This step deletes the current volume,
so back it up first if you might need it.

```bash
kubectl scale statefulset/inputlayer --replicas=0
kubectl wait --for=delete pod/inputlayer-0 --timeout=120s
kubectl delete pvc inputlayer-data
kubectl apply -f deploy/kubernetes/base/pvc.yaml   # only the PVC: re-applying the overlay would also restore replicas: 1
kubectl apply -f deploy/kubernetes/maintenance/maintenance-pod.yaml
kubectl wait --for=condition=Ready pod/inputlayer-maintenance --timeout=180s
kubectl exec -i inputlayer-maintenance -- tar -C /var/lib/inputlayer/data -xzf - < inputlayer-backup.tgz
kubectl delete pod inputlayer-maintenance
kubectl scale statefulset/inputlayer --replicas=1
kubectl rollout status statefulset/inputlayer
```

If your overlay changes the PVC (storage class, size), apply your overlay's
rendered PVC instead of `base/pvc.yaml`. CSI `VolumeSnapshot`s also work
as backups. Take them while the StatefulSet is scaled to 0, and restore by
creating `inputlayer-data` from the snapshot (`spec.dataSource`).

## Resource Sizing

### Memory

InputLayer holds the active working set in memory via Differential Dataflow. Memory usage is proportional to the number of facts, rules, and active computations.

| Workload | Facts | Rules | Recommended Memory |
|---|---|---|---|
| Development | < 100K | < 50 | 512 MB |
| Small production | 100K - 1M | 50 - 200 | 2 - 4 GB |
| Medium production | 1M - 10M | 200 - 1000 | 8 - 16 GB |
| Large production | 10M+ | 1000+ | 32 GB+ |

Two limits keep the server inside that memory and refuse work with
`resource_exhausted` instead of growing past it:

- `max_graph_memory_bytes` bounds the **stored data**: the facts of one
  knowledge graph, as estimated from their tuples.
- `max_query_memory_bytes` bounds a query's **working set**: everything it
  holds while it evaluates. A query copies the facts it reads into its
  dataflow, and joins and recursive rules hold intermediate results on top,
  so its working set is a multiple of the data it reads. Keep the per-query
  limit at least twice the graph budget, so a query that scans a whole graph
  inside its budget still runs; raise it further for joins and recursion over
  large relations.

Size the container for the sum: every graph's budget, plus
`max_query_memory_bytes` for each query running at once (up to about three
quarters of the CPUs), plus the server itself.

### CPU

Differential Dataflow benefits from multiple cores for parallel dataflow computation. The `num_threads` setting (default: `0`, meaning all available cores) controls worker parallelism.

| Workload | Recommended CPU |
|---|---|
| Development | 2 cores |
| Small production | 4 cores |
| Medium production | 8 cores |
| Large production | 16+ cores |

### Disk

The data directory stores WAL files and compacted batch files. Disk usage depends on fact volume and the WAL rotation settings.

- WAL files rotate at 64 MB by default (`max_wal_size_bytes`)
- Batch files are compacted when a shard exceeds 10 files (`auto_compact_threshold`)
- Plan for 2-3x the raw data size to account for WAL overhead and compaction headroom

Use fast local storage (SSD/NVMe) for the data directory. Network-attached storage works but increases write latency, which impacts durability mode `immediate`.

### File Descriptors

For production deployments with many concurrent WebSocket connections, increase the file descriptor limit:

```bash
# In systemd service
LimitNOFILE=65536

# Or system-wide in /etc/security/limits.conf
inputlayer    soft    nofile    65536
inputlayer    hard    nofile    65536
```

## Security Recommendations

### Authentication

InputLayer requires WebSocket authentication for all data operations. On first boot, if no admin password is configured, a random password is generated and printed to stderr. For production:

1. Always set `INPUTLAYER_ADMIN_PASSWORD` explicitly
2. Use Kubernetes Secrets or Docker secrets for the password
3. Rotate credentials periodically

### Network

1. Bind the server to `127.0.0.1` when behind a reverse proxy (the default)
2. Use a reverse proxy for TLS termination -- InputLayer does not terminate TLS natively
3. Enable rate limiting via `http.rate_limit.per_ip_max_rps` for public-facing deployments
4. Restrict CORS origins in production (`http.cors_origins` instead of `http.cors_allow_all`)

### Filesystem

1. Run as a dedicated non-root user
2. Use `ProtectSystem=strict` in systemd to prevent writes outside allowed paths
3. Set appropriate permissions on the data directory (`750` or stricter)
4. Back up the data directory regularly with `inputlayer-backup` -- see [Backup and Restore](backup) (Kubernetes: [Backup and Restore](#backup-and-restore))

### Durability

For production, always use `durability_mode = "immediate"`. The server warns on startup if a weaker mode is configured:

```
WARNING: Durability mode is Batched (not Immediate).
Recent writes may be lost on crash.
```

Also ensure `storage.persist.enabled = true`. Without it, all data is lost on restart:

```
WARNING: DD-native persist layer is DISABLED.
Data will NOT survive restarts.
```
