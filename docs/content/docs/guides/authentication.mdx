# Authentication

InputLayer requires authentication for all connections. The server bootstraps an admin user on first start.

## Bootstrap Admin

On first launch, the server creates a default admin account:

- **Username**: `admin`
- **Password**: Set via `INPUTLAYER_ADMIN_PASSWORD` environment variable, or auto-generated (printed to stderr) if unset

> **Important**: Always set `INPUTLAYER_ADMIN_PASSWORD` in production deployments.

```bash
INPUTLAYER_ADMIN_PASSWORD=my-secure-password inputlayer-server
```

Or in configuration:

```toml
[http.auth]
bootstrap_admin_password = "my-secure-password"
```

## User Management

Manage users via REPL commands (requires admin privileges):

### Create User

```
.user create alice secretpassword viewer
```

Roles: `admin`, `editor`, `viewer`

### List Users

```
.user list
```

### Delete User

```
.user drop alice
```

### Change Password

```
.user password alice new-secret
```

Changing a password ends every live session that logged in with the old one (see [Revocation](#revocation)). Sessions opened with the user's API keys keep working.

### Change Role

```
.user role alice editor
```

## Knowledge Graph Access Control

Control which users can access which knowledge graphs.

### Grant Access

```
.kg acl grant mydb alice viewer
.kg acl grant mydb alice editor
.kg acl grant mydb alice owner
```

### Revoke Access

```
.kg acl revoke mydb alice
```

### List ACLs

```
.kg acl list mydb
```

### Permission Levels

| Level | Capabilities |
|-------|-------------|
| `viewer` | Query data, list relations and rules |
| `editor` | Insert/delete facts, create/modify rules, manage indexes |
| `owner` | Drop knowledge graphs, manage ACLs for this KG |

Permissions are cumulative - `editor` includes `viewer`, `owner` includes `editor`.

## WebSocket Authentication

Every WebSocket connection must authenticate before sending queries.

### Auth Handshake

After connecting to `ws://host:port/ws`, the first message must be an auth request:

```json
{
  "type": "login",
  "username": "admin",
  "password": "admin"
}
```

Or with an API key:

```json
{
  "type": "authenticate",
  "api_key": "your-api-key"
}
```

The server responds with:

```json
{
  "type": "authenticated",
  "session_id": "a1b2c3d4",
  "knowledge_graph": "default",
  "version": "0.1.0",
  "role": "admin"
}
```

Or on failure:

```json
{
  "type": "auth_error",
  "message": "Invalid credentials"
}
```

The server allows 30 seconds for authentication. Any non-auth message before authentication results in disconnection.

## REST API Authentication

REST endpoints (except health/live/ready) require a Bearer token:

```bash
curl -H "Authorization: Bearer your-api-key" http://localhost:8080/metrics
```

## API Keys

API keys provide machine-to-machine authentication without passwords.

### Create API Key

```
.apikey create my-service-key
.apikey create ci-deploy 90d
```

The reply holds the key itself. It is shown only once; the server stores only its hash. An optional TTL makes the key expire that long after creation: a number and a unit, `ms`, `s`, `m`, `h` or `d` (for example `30s`, `15m`, `24h`, `90d`). Without one the key never expires.

### List API Keys

```
.apikey list
```

| Column | Meaning |
|--------|---------|
| `label` | the key's name |
| `owner` | the user the key authenticates as |
| `created_at` | when it was created; null for keys created before key timestamps were recorded |
| `expires_at` | when it expires; null if it never does |
| `last_used_at` | the last authentication with it; null if never used |
| `status` | `active` or `expired` |

Timestamps are Unix milliseconds. `last_used_at` is updated at most once per second per key, in memory, and persisted once a minute and at shutdown, so after a crash it can be up to a minute old. A REST request counts as a use; a WebSocket connection counts once, when it authenticates. Use it to find stale keys.

### Expire API Key

```
.apikey expire my-service-key 24h
```

Brings the key's expiry forward to that long from now. An expiry can only be brought forward, never extended; to extend access, create a new key. `.apikey expire <label> 0s` expires the key immediately but keeps it listed, unlike `.apikey revoke`.

When an expiry passes, the key stops authenticating (`API key expired`), and every session using it ends as described in [Revocation](#revocation). Expired keys stay listed with status `expired` until revoked.

### Revoke API Key

```
.apikey revoke my-service-key
```

Revoking a key ends every live session authenticated with that key and deletes it. Other keys, including other keys of the same user, are unaffected.

### Rotate API Key

Rotation replaces a key without downtime: both keys work during a grace period, then the old one expires.

1. Create the replacement: `.apikey create my-service-key-2 90d`
2. Bring the old key's expiry forward to the grace period: `.apikey expire my-service-key 24h`
3. Deploy the new key to every client within the grace period. Sessions on the old key keep working until it expires, and new sessions can use either key.
4. After the grace period, the old key is rejected and its remaining sessions end. Remove it from the list with `.apikey revoke my-service-key`.

`last_used_at` on the old key shows whether any client still uses it.

## Revocation

Each WebSocket session is bound to the credential it authenticated with: one API key, or the password a user had at login. The binding takes effect as soon as the command that changes the credential returns:

| Command | Ends sessions authenticated with |
|---------|----------------------------------|
| `.apikey revoke <label>` | that key |
| `.apikey expire <label> <ttl>` | that key, once the TTL passes |
| `.user password <name> <password>` | the user's previous password |
| `.user drop <name>` | the user's password and all of the user's API keys |

A key's expiry passing ends its sessions the same way, from the expiry instant. Once a credential is revoked or expires, no further results, notifications or subscription pushes are admitted to the session's transport; frames admitted before then can still arrive afterward. A request still running at that point has its reply withheld; writes it already committed stay committed. The server stops the session's standing queries, sends a final [`credential_revoked` notice](websocket-api#notices) and closes the connection.

For an expired key the notice is `credential_expired`, with the message `Credential expired; reconnect with valid credentials`.

`.user role` takes effect on the next request of every live session of that user without closing them. REST requests check the API key on every request.

If a password or role replacement deletes the old user but fails to insert its
replacement, all of that user's live credentials are revoked. Recreating the
user removes any orphaned API keys in the same transaction that creates the new
user, before publishing credentials. This also applies to admin bootstrap after
a restart: old keys cannot bind to the recreated account, and bootstrap does
not issue an API key when recovering an existing internal auth graph, even if
the old key rows have already been removed. Automatic key issuance happens only
when the internal auth graph is first created. For recovery, log in with the
bootstrap password and create a new key instead.

You can also set an API key for the CLI client via environment variable:

```bash
export INPUTLAYER_API_KEY=your-api-key
inputlayer-client
```

## Python SDK Authentication

```python
from inputlayer import InputLayer

# Username/password
async with InputLayer("ws://localhost:8080/ws", username="admin", password="admin") as il:
    ...

# API key
async with InputLayer("ws://localhost:8080/ws", api_key="your-key") as il:
    ...
```

## Security Best Practices

1. **Change the default admin password** immediately after deployment
2. **Use TLS** via a reverse proxy (see [Deployment](deployment)) - credentials are sent in plaintext over WebSocket
3. **Create per-user accounts** rather than sharing the admin account
4. **Use API keys** for automated services and CI/CD pipelines
5. **Grant minimum required permissions** - use `viewer` access for dashboards, `editor` for ETL jobs
6. **Bind to localhost** when using a reverse proxy: set `host = "127.0.0.1"` in config
7. **Give API keys a TTL** and [rotate](#rotate-api-key) them before it passes; revoke keys whose `last_used_at` shows they are unused
