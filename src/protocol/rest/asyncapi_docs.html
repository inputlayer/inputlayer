Connection

Endpoint
ws://<host>:<port>/ws
Protocol
WebSocket (RFC 6455)
Message Format
JSON text frames
Query Parameters
kg — Knowledge graph to bind to (default: "default")

Connection Lifecycle

  1. Client connects to /ws?kg=<name>
  2. Client sends login or authenticate; the server creates a session and answers authenticated (with protocol_version, currently 3) or auth_error
  3. Client sends execute messages, server responds with result or error
  4. Server may push change notifications (persistent_update, ...), subscription_delta messages (streamed when large) and connection notices
  5. Client disconnects → server auto-closes the session

Request IDs

Any request may carry an id (a non-empty string of at most 64 bytes). Every frame answering it — authenticated, auth_error, result, result_start, result_chunk, result_end, error, pong — echoes it. Pushes and notices never carry an id, so they cannot be mistaken for a reply. A malformed request (or one whose id is invalid or given twice) gets exactly one error with code invalid_request, carrying the id when it could be read; the connection stays usable.

Deadlines and cancellation

Every execute runs under one deadline, counted from when the server reads it: queueing, admission and computation together. It is storage.performance.query_timeout_ms, or the request's timeout_ms when sooner. A cancel names an unanswered request by its id and acts on arrival; its cancel_ack says cancelled (nothing applied; the target fails with code cancelled), too_late (it finished or began committing, which is never interrupted) or not_found. An expired request fails with deadline_exceeded; outcome_unknown means a commit failed in a way that may have applied it.

Revision preconditions

An execute that writes may carry expect_revision, a revision the client observed (a subscription's or a push's revision). Its writes then commit only if no relation in scope and no persistent rule changed after that revision, checked under the knowledge graph's write lock. The scope is expect_relations plus every relation they are derived from through persistent rules, or the whole knowledge graph when absent. A refused program applies nothing and fails with precondition_failed; of several writers expecting one revision of one scope, at most one commits, but only when each writer's program writes a relation in that scope. Writes outside the scope do not refuse each other, so racing deciders that write a claim relation should include it in expect_relations or rely on the claim guard. expect_epoch (authenticated.stream_epoch) refuses a revision from another engine run. A program that does not write persistent state cannot carry expect_revision (invalid_request).

Client → Server Messages

SEND

execute

Execute any Datalog statement or meta command as raw text.

typestringAlways "execute"
idstring?Request id, echoed on every reply
programstringThe Datalog statement or meta command
timeout_msinteger?Deadline from arrival, capped by the server's query timeout
expect_revisioninteger?Commit only if state in scope is unchanged since this revision (see Revision preconditions)
expect_relationsstring[]?Scope of expect_revision: these relations and what derives them; absent: the whole knowledge graph
expect_epochstring?Stream epoch expect_revision belongs to
{"type": "execute", "id": "7", "program": "?edge(X, Y)"}
SEND

cancel

Cancel the unanswered request target. Answered by cancel_ack with outcome cancelled, too_late or not_found.

{"type": "cancel", "id": "9", "target": "7"}
SEND

ping

Keep-alive ping. Server responds with pong.

{"type": "ping", "id": "8"}

rolestringRole of the credential

 "version": "0.1.0", "role": "admin", "protocol_version": 3}

Command or query execution result.

rowsany[][]Result rows
row_countintegerNumber of rows returned

truncatedbooleanWhether results were truncated

 "row_count": 2, "total_count": 2, "truncated": false, "execution_time_ms": 5, "errors": []}
RECV

error

A request failed as a whole. Always a reply; connection events are notices.

typestringAlways "error"
idstring?The request's id, when it could be read
messagestringHuman-readable error message
codestring?validation, not_found, conflict, unsupported, internal, invalid_request, rate_limited, deadline_exceeded, cancelled, outcome_unknown, store_read_only, resource_exhausted, precondition_failed, replica_unconfirmed or access_denied
{"type": "error", "id": "7", "message": "Knowledge graph 'missing' not found", "code": "not_found"}
RECV

pong

Response to a ping message.

{"type": "pong", "id": "8"}
RECV

notice

A connection event, sent unprompted and never with an id. Every code but notifications_missed is followed by the server closing the connection.

codestringnotifications_missed, slow_consumer, idle_timeout, lifetime_exceeded, auth_timeout, credential_revoked, credential_expired or server_shutdown
messagestringHuman-readable description
{"type": "notice", "code": "idle_timeout", "message": "Idle timeout"}
RECV

persistent_update / rule_change / schema_change / kg_change

Push notification when persistent data changes in the session's knowledge graph.

typestringEvent kind
knowledge_graphstringKG where the change occurred
relationstringRelation that was modified (persistent_update)
operationstringe.g. "insert", "delete", "registered", "dropped"
countintegerNumber of tuples affected (persistent_update)
seqintegerMonotonic sequence number for replay
{"type": "persistent_update", "knowledge_graph": "default",
 "relation": "edge", "operation": "insert", "count": 5,
 "timestamp_ms": 1700000000000, "seq": 42}
RECV

subscription_delta

Change to a standing query's result (after .subscribe <id> ?<query>). Set semantics; persistent data only.

subscriptionstringClient-chosen name
generationintegerThe registration it belongs to, as in the .subscribe reply's subscribed
knowledge_graphstringKG the subscription is bound to
seqintegerPer-subscription delta number, starting at 1
columnsarrayColumn names
insertedarrayRows now in the result (sorted)
retractedarrayRows no longer in the result (sorted)
{"type": "subscription_delta", "subscription": "late", "generation": 1,
 "knowledge_graph": "default", "seq": 1, "columns": ["Order"], "inserted": [[1042]], "retracted": []}
RECV

subscription_delta_start / subscription_delta_chunk / subscription_delta_end

A delta whose frame would exceed 1 MiB, streamed as one logical delta: the start frame carries what subscription_delta does but its rows; chunks of at most 500 rows and about 1 MiB follow from chunk_index 0; the end frame gives chunk_count, inserted_count and retracted_count. Apply the delta only at its end, once the chunks add up. Other frames may arrive in between.

{"type": "subscription_delta_start", "subscription": "late", "generation": 1,
 "knowledge_graph": "default", "seq": 2, "revision": 18, "columns": ["Order"]}
{"type": "subscription_delta_chunk", "subscription": "late", "generation": 1, "seq": 2,
 "chunk_index": 0, "inserted": [[1043]], "retracted": []}
{"type": "subscription_delta_end", "subscription": "late", "generation": 1, "seq": 2,
 "chunk_count": 1, "inserted_count": 1, "retracted_count": 0}
RECV

subscription_error

Re-evaluation of a standing query failed, or the subscriber may no longer read the knowledge graph. The subscription stays registered; its next delta is relative to the last result it received. code is access_denied when read access was lost, and absent otherwise.

{"type": "subscription_error", "subscription": "late", "generation": 1, "message": "Access denied", "code": "access_denied"}
RECV

subscription_reset

The server could not deliver the subscription's next change whole (a row larger than any frame, or read access was revoked) and removed the subscription. Discard its rows, including a streamed delta in progress, and subscribe again.

{"type": "subscription_reset", "subscription": "late", "generation": 1, "message": "..."}

Examples

Insert and Query Data

// Insert persistent facts
→ {"type": "execute", "program": "+edge[(1, 2), (2, 3), (3, 4)]"}
← {"type": "result", "columns": ["message"], "rows": [["Inserted 3 fact(s) into 'edge'."]], ...}

// Query
→ {"type": "execute", "program": "?edge(X, Y)"}
← {"type": "result", "columns": ["X", "Y"], "rows": [[1, 2], [2, 3], [3, 4]], "row_count": 3, ...}

Add a Rule and Query Derived Data

// Add persistent rule
→ {"type": "execute", "program": "+path(X, Y) <- edge(X, Y)"}
← {"type": "result", "columns": ["message"], "rows": [["Rule added for 'path'."]], ...}

→ {"type": "execute", "program": "+path(X, Z) <- path(X, Y), edge(Y, Z)"}
← {"type": "result", "columns": ["message"], "rows": [["Rule added for 'path'."]], ...}

// Query derived view
→ {"type": "execute", "program": "?path(X, Y)"}
← {"type": "result", "columns": ["X", "Y"], "rows": [[1, 2], [1, 3], [1, 4], [2, 3], [2, 4], [3, 4]], ...}

Session-Scoped Data

// Add ephemeral fact (no + prefix)
→ {"type": "execute", "program": "temp_data(100)"}
← {"type": "result", "columns": ["message"], "rows": [["Session fact added for 'temp_data'. ..."]], ...}

// Add ephemeral rule (no + prefix)
→ {"type": "execute", "program": "doubled(X, Y) <- temp_data(X), Y = X * 2"}
← {"type": "result", "columns": ["message"], "rows": [["Session rule added for 'doubled'."]], ...}

// Query combines persistent + ephemeral data
→ {"type": "execute", "program": "?doubled(X, Y)"}
← {"type": "result", ..., "row_provenance": ["ephemeral"], ...}

Knowledge Graph Management

// Switch KG
→ {"type": "execute", "program": ".kg create analytics"}
← {"type": "result", ..., "switched_kg": "analytics"}

// List KGs
→ {"type": "execute", "program": ".kg list"}
← {"type": "result", "columns": ["message"], "rows": [["  default"], ["* analytics"]], ...}
